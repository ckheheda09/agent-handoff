# 故障处理

先保留真实工具响应和脱敏错误，区分目录可见、密文可下载、正文可解密、模型已开始四个状态。

## 新设备能看到会话，但不能读取

`readable: false`、`access_state: "waiting_source_sync"` 或 resume 的 `status: "waiting_source_sync"` 表示等待**源设备**补充加密权限。不是空会话，也不是被另一个 Agent 领取后消费掉。

源设备需使用客户端 0.7.1+、Relay 0.5.1+，保留原 age 私钥并保持 MCP 在线；其心跳约每 30 秒为后来加入且已登记公钥的授权设备同步自己的历史会话。在源设备调用 `handoff_sessions` 也会触发同步。接收端随后重试原编号，无需重新上传或改标题。

检查列表响应的 `synchronization.errors`，有错误则说明实际原因。不要为了消除报错无限轮询；源设备离线时告知用户所需操作，源设备恢复后再试。源私钥丢失时中转无法代为解密，应从源设备备份恢复；不可声称服务器能修复旧密文权限。

## 正文为空或解密失败

确认选中的共享 ID、Relay/profile 与设备身份，检查 resume 是否返回等待同步或错误；工具返回摘要文件路径时读取文件内容，不能把缺少内联字段当成空会话。若成功响应的 `context` 和 `next_steps` 确实都为空，报告内容异常，不伪造上下文，也不覆盖原会话。

不要删除接收记录、轮换凭证或重新注册设备来处理加密问题；这些操作不会恢复原私钥。相同会话可重复读取，已有其他设备的 `received` 不应阻止本设备接收。

## 其他常见结果

| 结果 | 下一步 |
| --- | --- |
| 没有工具，但 doctor 通过 | 在目标宿主重载 MCP，确认加载的是正确 profile；配置落盘不等于模型有工具 |
| `unauthorized` | 检查设备是否被删除或凭证轮换；必要时由管理员按接入流程处理，保留原私钥 |
| TLS 证书错误 | 核对传输 origin、主机名与可信 CA；分别检查 npm 下载 CA 和客户端连接 CA |
| 列表确实为空 | 核对中转及分页；默认会话保留 30 天，也可能从未成功发布，不推断被其他 Agent 接收后删除 |
| 同名会话 | 按来源、时间、编号让用户选，之后用精确 ID 接收 |
| 只有提醒，没有模型响应 | 提醒依赖运行中的宿主、MCP 与桌面权限，不证明任务被接受或模型自动启动 |

正文使用 age 在本地加密，中转保存密文及标题、来源、时间等元数据。删除设备可阻止后续服务器访问，但无法收回对方已经下载的内容。共享摘要不附文件，不等同于原生聊天数据库备份。
